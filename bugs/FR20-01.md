# FR20-01 - Mobile Add to Cart accepts an empty quantity

| Field | Value |
|---|---|
| Finding | FR20-01 |
| Requirement | FR20 |
| Severity | High |
| Test cases | D-UI-01 |
| GitHub Issue | https://github.com/tkob-team/eshop-sut/issues/153 |

## Summary

Mobile Add to Cart accepts an empty quantity. This issue covers the specific condition represented by D-UI-01.

## Environment

- Baseline: `85af3ba875c88283615e22cb108f13e2fccaf0e9`.
- Selected requirement: FR20; oracle: FR-20 mapped to FR-06 positive integer quantity.
- Interface: UI.
- Severity: High.
- Isolated demo source/database; no fix applied to the original SUT.

## Preconditions

Start a disposable copy of the fixed baseline. For API calls obtain a JWT through `POST /api/login`: regular user `test@eshop.com` / `Test1234!`, admin `admin@eshop.com` / `Admin123!`. These are public demo fixtures, not personal credentials. Use JSON requests and the role shown in the captured request. The server clock for API cases is fixed at `2026-10-19T08:00:00.000Z`.

Use the unchanged Mobile app in Expo Go/Android, sign in and open a seeded product detail. For quantity tests empty the cart before the action and keep the selected product and stock unchanged. Original screenshots show the actual fixture account; their exact capture timestamps were not reconstructed.

## Steps to reproduce

1. Open the product detail with an empty cart.
2. Replace the entire quantity field with `""` (the quotation marks denote the input literal).
3. Tap Add to Cart and record the response.
4. Open the cart without editing it and compare the item state.

## Expected result

Reject empty quantity; no new cart item.

## Actual result

The app displays successful-add feedback for the invalid quantity. The captured cart shows quantity=1.

The original capture does not carry a reconstructed execution timestamp.

## Impact

The product-detail acceptance or display criterion is violated for the documented input. Only the feedback and cart state visible in the supplied captures are claimed.

## Root cause

The Mobile handler coerces the quantity with parsing/fallback instead of validating the full input.

[Affected source at the fixed baseline](https://github.com/tkob-team/eshop-sut/blob/85af3ba875c88283615e22cb108f13e2fccaf0e9/frontend-mobile/App.js).

## Suggested correction

Validate the complete input as a positive integer before changing cart state.
